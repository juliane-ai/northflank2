# Discord 方向观察、保本滑动止盈与重复入场研究

初稿：2026-09-15。2026-09-16 状态更新：独立本地模拟服务、最小模拟开平仓与 ZeroClaw 只读分析已验证，见 [运行指南](signal-research.md)；尚无完整策略回测或收益结论。当前开发优先级见 [项目方向与验证顺序](project-direction.md)。用户已确认第一阶段使用真实行情模拟，记录结果。

## 已确认的产品目标

用户通过 Discord 发送文字或截图，提供品种与偏多／偏空方向。系统持续观察 OKX 永续合约，在波动条件合适时模拟开仓；浮盈达到条件后争取成本保本，随后沿有利方向移动止盈线；保护性退出后保留方向观察任务，等待新的回落／反弹机会再入场。主要持仓周期为数小时到数天。

输入可以只有方向，不要求原作者提供完整入场、止损和目标。系统应生成独立且可复现的计划，将“图片事实”“用户指定方向”“策略推导条件”分开保存。原作者的仓位大小、杠杆、盈利状态都不能直接沿用。

研究重点调整为退出保护和重复入场。此前“收到即跟、回踩、突破”三种入场方式不再作为第一轮的主实验；先固定一种入场方法，再比较退出与重开规则。这与 `research-roadmap.md` 的保本、滑动保护和重复入场方向衔接。

## 策略的两层状态

方向观察任务保存品种、方向、用户来源、有效期、失效条件和本任务总风险预算。每一次入场生成一个独立交易轮次，保存自己的成本、数量、初始止损、最高／最低有利价、保护线、退出原因和净结果。

```text
方向观察
  → 等待回落／反弹与确认
  → 模拟持仓（初始止损已存在）
  → 浮盈足够：启用成本保本保护
  → 有利价格继续延伸：单向移动保护线
  → 保护触发并完成模拟退出
  → 冷却、等待新的波动
  → 方向仍有效且预算允许：新轮次
```

到期、用户取消、方向失效、行情异常或风险预算耗尽会暂停／结束方向任务。盈利退出不会自动结束观察任务，也不会自动证明下一笔仍值得开。

“持续关注”由独立后台行情任务实现，需持久化并支持重启恢复；不依赖 AI 的聊天记忆或网页轮询。这些模块现已在 `src/signals` 实现并在本地运行；截至本次核对，尚无活动方向任务。

## “保本”的可实现边界

目标是减少盈利回吐与浮盈转实亏，不能保证任何一笔或账户永远不亏，也无法事先识别整段行情的最高／最低点。

- 入场后可能直接亏损，因此在保本启用前必须有初始止损。
- 浮盈尚未覆盖进出费用、点差、滑点与资金费时，回到开仓价退出仍可能净亏损。
- 启用保本后，保护线是计划触发价；跳空、延迟、深度不足等仍可能造成不利成交。
- 越早、越紧的保护通常更容易被正常波动触发；较宽的保护则允许更多利润回吐。两者需在相同数据上比较。
- 多次小盈利或小亏损后的一次大亏损可能抹去累计收益，所以要评价整个方向任务及账户净结果。

OKX 的说明区分了触发价、委托价和实际成交价；行情波动与深度不足可能导致不成交或部分成交。[OKX 止盈止损执行说明](https://www.okx.com/en-eu/help/why-didnt-the-tp-sl-execute-at-the-set-price)

## 第一版候选：波动归一化入场 + 两阶段保护

以下全部是待验证的模拟参数，不是已证实的盈利参数或实盘建议。第一轮固定参数，避免一边看结果一边改规则。

### 1. 方向与波动

- 用户消息设定偏多或偏空；新消息反向时生成新版本，暂停旧方向的新开仓。已有仓位按既定规则管理，不能悄悄变更方向。
- 候选趋势过滤：使用已收盘 1 小时 K 线；偏多时 EMA20 > EMA50 且收盘价 > EMA50，偏空时对称。未满足则等待。它只是可测试的过滤规则，不保证原作者正确。
- 用已收盘的 15 分钟 K 线计算 ATR(14)，作为近期典型波动的价格尺度。每次进入等待阶段冻结当时的 ATR，记为 A；首次成交时另存 A_entry，供该轮保护使用。
- 行情不新鲜、历史不足、合约无法准确映射、交易受限或成本异常时不生成模拟成交。

### 2. “跌到什么程度再买”

偏多任务：从开始有效观察后的最高价计算回落；达到 `1.5 × A` 后，仅进入“等待止跌确认”。候选确认采用后续一根已收盘 15 分钟 K 线收盘价超过前一根 K 线最高价，并且上述 1 小时方向过滤仍满足。下一条可执行报价才用于模拟入场。

偏空任务：从观察后的最低价计算反弹；达到 `1.5 × A` 后等待转弱确认，即后续 15 分钟收盘价低于前一根 K 线最低价，且小时方向过滤仍满足，再评估开空。

数值只是实验起点。“最近 15 分钟典型波动为 0.4%”时，1.5 倍约对应 0.6% 的回落／反弹；需用当时真实 A 计算，不能把此示例当作当前 ETH 阈值。

极端逆向变化、方向过滤失效或等待超时会使该次入场候选失效，重新进入观察。首轮可设逆向幅度超过冻结参考点的 3A 时取消候选；3 根确认 K 线内未确认也取消。取消后必须等待新的已收盘小时数据通过方向过滤，才能重新冻结参考点；不能在每次报价时重置参考点绕过限制。

没有原止损并不阻止登记方向。系统在每次模拟入场前计算初始止损和对应数量，明确标注为系统规则。首轮候选初始止损距离为 `2 × A_entry`，并检查该距离是否合理覆盖成本；不为了容纳亏损而扩大止损。

### 3. 盈利后先争取成本保本

所有计算以我们本轮的模拟成交均价 P0 与剩余仓位 Q 为基准。原作者较早的开仓价仅作参考。

设 C 为每单位持仓的进出费用、资金费及预估平仓滑点成本，b 为额外缓冲：

- 多头成本保本价 B = P0 + C + b。
- 空头成本保本价 B = P0 - C - b。

这是固定数量线性合约的简化表达；实际费用随成交价格、持仓时间与资金费事件变化时，需重新计算可平仓净结果，不能机械使用固定差值。

初始实验的保本启用条件：有利价格移动至少 `max(A_entry, C + b + 0.5 × A_entry)`。此时才将保护线推至成本保本区域，并保留最小波动余地。未满足时维持初始止损。

### 4. 随盈利单向移动保护线

设 d = `1 × A_entry` 为本轮固定追踪距离。记录持仓以来可获得的最高有利价 H（多头）或最低有利价 L（空头），启用保本后：

- 多头：新保护线 = max(旧保护线, B, H - d)。价格下跌触及保护线则退出。
- 空头：新保护线 = min(旧保护线, B, L + d)。价格上涨触及保护线则退出。

保护线只能向盈利方向收紧。未来波动扩大、模型改变看法或资金费变化都不能让它往亏损方向放宽。如果更新后的成本要求或当前行情已使保护条件无法成立，立即记录并退出／暂停，而非倒改历史。

模拟必须区分报价、标记价格与最新成交价格。建议第一版用可执行买卖报价评估退出：多头卖出用买盘，空头买回用卖盘。保护逐条行情检查，不等待 15 分钟 K 线收盘；15 分钟仅用于波动尺度与入场确认。行情中断时禁止新开并记录保护不可用区间，恢复后按可得价格处理，不能假造断线期间的成交。未来映射到交易所原生追踪单时，单独核验该订单支持的触发源、部分成交保护和改单语义，不能假设两者完全等价。

OKX 原生追踪单支持按比例或固定距离追踪有利行情，逆向达到距离后提交市价平仓单。它可作为将来的执行工具，但不自动包含本研究的成本保本、观察任务与重开预算。[OKX 追踪止损说明](https://www.okx.com/en-gb/help/how-to-use-trailing-stop)

### 5. 保护退出后再研究下一轮

- 必须先确认本轮已完全平仓，再开始新轮次；每轮数量按本轮止损距离与剩余风险预算计算。
- 候选冷却时间为 2 根 15 分钟 K 线；到时只获得重新评估资格，不自动开仓。
- 冷却结束后重新冻结参考点与 ATR，等待新的 1.5A 逆向波动及确认。不能止盈后在同一个价位立即开回去，也不能重复消费上一轮的确认事件。
- 多头盈利退出后，研究回落后再开多；空头盈利退出后，研究反弹后再开空。空头退出后“急跌买多”属于方向切换，应另建策略实验。
- 首轮仅允许实际模拟净结果非负的保护退出进入自动重开研究；若保护触发但滑点后亏损，或触发初始止损，则暂停该方向任务并重新评估。
- 同一方向任务建议最多 3 轮（首次 + 2 次重开）；若连续两轮的净收益不足该轮总交易成本，则暂停，避免来回缴费。重复转发不增加次数或预算。
- 方向观察任务先用接收后 24 小时有效期；每轮最大持仓先用 48 小时。任务到期不再开新仓，已有仓位仍按保护规则退出。以上都是模拟实验参数，可在测试前调整。

## 虚构价位演示

仅解释机制，不是历史回测或实时报价：多头在 100 入场，预估往返总成本为 0.15，缓冲 0.05，因此保本保护线至少为 100.20。为便于展示，示例启用价为 100.60，追踪距离为 0.40：

1. 上涨到 100.60：启用保护，保护线 100.20。
2. 上涨到 101.00：保护线提高到 100.60。
3. 上涨到 102.00：保护线提高到 101.60。
4. 回落到 101.60：触发退出；成交按之后可获得的报价模拟，不保证恰好是 101.60。
5. 退出后继续观察。后续回落本身不构成入场，仍需冷却、回落幅度和确认全部满足。

如果价格从 100 直接下跌，则保本阶段不会启用；如果从高位跳过保护线，实际模拟结果也应反映不利成交。空头规则对称，保护线随最低价下移。

## 研究如何判定有效

对同一批方向任务，冻结相同的首次入场和风险预算，比较：

| 组别 | 退出／重开规则 |
| --- | --- |
| 对照 | 只用初始止损与固定最长持仓，不做保本或追踪 |
| 保本组 | 达到条件后推到成本保本，随后固定保护价，不重开 |
| 追踪组 | 成本保本 + 单向追踪，不重开 |
| 完整组 | 成本保本 + 单向追踪 + 有条件重开 |

原作者后续真实退出数据完整时，可额外加入等待原作者退出的对照。仅有截图时不能伪造原作者的整段持仓路径。

主要指标：每个方向任务的累计净收益、最大回撤、浮盈转净亏比例、保本启用后仍净亏的比例、利润回吐、再入场贡献、成本占毛利润比例、连续小损次数。盈利保留率仅对最大净浮盈为正的样本计算，并同时展示漏掉的大趋势与大亏损。

输入统计覆盖未成交、失效、模糊和亏损任务；同一原始来源重复转发不算独立样本。按时间划分开发与后续验证样本，以接收时可见的信息推进，不能使用未来消息、未收盘 K 线的最终值或整段行情最高点。

初始比较不靠提高杠杆美化回报。可沿用每组独立 10,000 USDT 虚拟资金、每轮计划风险 25 USDT；一个方向任务预留累计计划风险不超过 75 USDT，组合同时未平仓计划风险也不超过 75 USDT。已实现盈利不自动扩张预算，跨轮已实现亏损加当前风险需受剩余预算约束。实际亏损可因跳空超过计划，必须如实记录。

报价不完整、仅有 OHLC 而无法确定同一根 K 线内最高价、保护更新和触发先后时，使用更细行情或保守假设并报告不确定性。不能先用整根最高价抬保护线，再假设之前的低点按新线成交。

## Discord 与现有项目的接入

建议保存三类对象：原始消息与证据、方向观察任务、各轮交易与事件。数据库用独立 `signal_research` 数据区，保留策略与提示词版本、每次价格输入、保护线变动、退出及重开原因。原消息和截图里的自然语言是资料，不构成修改风控或直接执行的授权。

截图解析需验证 Discord 附件链路和当前模型图像能力；低可信字段先标记待核验。不同交易所的方向可以作为线索，但触发、成本与虚拟成交都使用目标 OKX 合约数据。聊天只产生计划和解释，行情处理与保护不依赖模型每隔几秒重新思考。

可复用当前 PostgreSQL 事务、单实例锁和生命周期事件思路。现已新增公共行情采集、方向任务调度、保护状态机、模拟账本及结果看板。当前 `MockOkxReadClient` 仅用于虚构界面预览，不能用于验证策略。当前 `/api/overview` 的页面驱动采集也不能承担后台保护任务。
